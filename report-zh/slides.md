## 第 2 張 — 它怎麼建的，以及為什麼這個基準是誠實的

**規則：** 指引中點 × (1 + 平均超額)，視窗長度由**訓練集內的巢狀 walk-forward** 選出。MAPE **4.10%**、命中率 **76.9%**。

早期版本在看過樣本**之後**才固定 8 季 —— 那是對基準做資料窺探，而訊號卻要接受 walk-forward 紀律。拿掉它反而讓基準**變好**（RMSE 0.0229 → 0.0200），訊號的門檻因此升高。對 live quarter，這條公平規則自己選出 8 季，所以數字不變。

Walk-forward 殘差：2025 年前 **−1.96pp**（7 次中 1 次為正）→ 2025 年起 **+0.53pp**（6 次中 5 次）。**2026Q2 是樣本內最大加速：+0.18pp。**

以營收歷史為錨的模型必須**推斷** regime 斷裂。以指引為錨的規則直接**繼承**它。

> **講稿。** 這張同時回答「2026 結構性斷裂怎麼辦」與「你的基準是不是在作弊」。
> 第二個問題重要 —— 我是被評審逼問之後才自己找到的，而修掉它讓我自己的立論更難成立。

## 第 3 張 — 對每個訊號套用的測試設計

**訊號：** npm 儀器化下載量（3 種構造 × 4 個視窗）· hyperscaler 雲端部門成長

1. **時點 vintage 面板** —— 特徵存成（季度、值、`available_from`）；揭露日取財報 8-K 而非 10-Q。13 個單元測試，其中一個把受前視污染的載入器換成拋錯替身後重建整個面板。
2. **每個候選都有配對負對照組**，含與 Datadog 無經濟關聯的安慰劑籃（`lodash`、`chalk`、`axios`、`react`）。
3. **七個基準**，含 ARIMA(1,1,0) 與不可事後挑選的指引規則。
4. **對指引正交化的版本** —— 特徵對指引隱含成長取殘差，因為可交易的問題是**預期差**而非水準值。
5. **題目指定的四個目標指標** —— 營收成長、相對指引超額、$100k+ 客戶數成長、billings。
6. **置換虛無、Diebold–Mariano（HLN）、10,000 次 bootstrap，以及檢定力分析。**

> **講稿。** 這裡花真正的時間；這才是交付物。特徵的先驗排序寫在 LOG.md D24、
> 在 Phase 4 執行前定案 —— 而我排第一的特徵輸了。那是系統在運作，不是系統失效。

## 第 4 張 — 結果，以及那個表觀訊號到底是什麼

### 24 格中 0 格勝過最強基準。對指引正交化後，仍然是 0 格。

**因果鏈，三個事實：**

- 對 **AR(1)**，24 格中 15 格低於 0.9；置換虛無給 0.58 → **p = 0.002**。特徵**確實**帶有 AR(1) 缺乏的資訊。
- 一個**純時間指標**走相同管線同樣打敗 AR(1)（0.896）。零 Datadog 內容。
- 對**最強**基準，同一虛無給 0.01 格，實際觀測是 **0**。

**那個資訊是漂移。設定正確的樸素模型本來就有它。**

佐證：安慰劑套件在 lag −2 到 +2 對營收相關全部是 **0.72–0.76** —— 平坦。且視窗拉長時表現**變差**（0.734 → 0.975）；真實訊號會銳化。

**這證明了什麼、沒證明什麼。** n=13 時，檢定偵測到 5% 邊際的機率只有 **6%**、10% 邊際是 **15%**。所以「0/24」是**界定**效果量上界，不是證明為零。但實際觀測到的格子在 **1.05–2.65** —— 那部分是測量結果，不是檢定力不足。

> **講稿。** p=0.002 不是矛盾，是轉折點。直白說：
>「打敗 AR(1) 聽起來像結果，直到你發現一個時鐘也打得贏 AR(1)。」

## 第 5 張 — 這個結論的範圍，講精確

| 管道 | 承載什麼 | 累計量 | 歷史 |
|---|---|---|---|
| npm 籃 *(我能測的)* | Node.js APM SDK | 11.3 億 | 每日，2017 起 |
| **Docker Hub `datadog/agent`** | **核心 Go agent —— 主機、容器、日誌** | **112.5 億** | **僅終身計數** |
| APT/YUM、Helm、雲市集 | 核心 Go agent | 未公布 | 無 |

**約 10 倍的量落在一條沒有歷史的管道上。**

> 結論**不是**「另類數據無法預測 Datadog」，而是：
> *可免費且有歷史地觀測到的那一片是錯的一片，而對的那一片無法回溯觀測。*

前瞻性的補救很便宜，也是這條管線價值最高的補強：每日對 Docker Hub 計數取快照，**從那天起**就有正確的序列。只是已經過去的 27 季救不回來。

> **講稿。** 這點要自己扛下來。我把分析建在容易觀測的管道而不是重要的那條，
> 而一次 API 呼叫在第一天就能抓到。它現在是產品化章節的第一項。

## 第 6 張 — 可以外推到別處的發現

# 每百萬美元營收對應下載量：21,818 → 97,228
### +346% · Spearman ρ = +0.927 · p < 0.0001 · 28 季近乎單調

**針對標準 SaaS 解釋做了測試，而非斷言。** 以揭露的 $100k+ ARR 客戶數正規化：

| | 前四季 → 後四季 |
|---|---|
| 每大客戶營收 | **+67%** |
| 每大客戶下載量 | **+644%** |

交叉銷售與階梯定價是**真的** —— 但每客戶下載量漲得約快 10 倍，故貨幣化只解釋少數。私有鏡像方向**相反**。CI/CD 重拉也不成立：工作日／週末比 6.39 → 5.61，p=0.77。

**計數對金額：** 下載量是未加權計數，計數型目標理應更合 —— 而它確實如此。對**客戶數成長最佳格 1.049**，對**營收成長 1.137**。方向正確，但仍是輸。

> **講稿。** 這是原創研究的時刻。停頓一下。它是一個可測量、可外推、
> 關於整類另類數據的陳述，不是事後檢討。

## 第 8 張 — 模板化，以及這對投研 agent 產品的意義

**指向 SNOW 或 MDB：** CIK + 營收標籤 · 含對照與安慰劑籃的訊號籃 · 重新指向的指引抽取器。其餘與標的無關。**不能移轉的是結論。**

| 元件 | 來自本專案的理由 |
|---|---|
| **先做可觀測性分流** | 這裡最大的錯誤是分析了容易的管道而非對的管道。一次 API 呼叫就能在建模前標出「高相關、零歷史」。 |
| **配對對照組為強制元資料** | 對照組把 0.79 的相關變成被否決的假設。沒有對照組的登錄表會出貨偽陽性。 |
| **時點 vintage 作為基礎設施** | 被問「第二季營收」時，agent 抓的是**今天**的值。此處第四季價值 18 天。測試該進 CI。 |
| **會回報檢定力的評估迴圈** | 每個負面結果都應附最小可偵測效果量，讓「沒找到邊際」不被讀成「邊際不存在」。 |

**交付物不是一個訊號 —— 而是一套能告訴你「你手上沒有訊號」的方法。**

> **講稿。** 收在這裡。那比一份回測更難偽造，也正是投研平台要被託付資金
> 就必須做對的事。
