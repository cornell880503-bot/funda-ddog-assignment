## 1. 結論

**2026 年第三季營收：$1,188.5m，95% 區間 $1,173.8m – $1,203.2m（±$14.7m）。隱含年增 +34.2%、季增 +6.0%。**

這個預估建立在 Datadog 自己的指引中點 $1,140m 之上 —— 已逐字核對 8-K Exhibit 99.1、accession 0001628280-26-053829：*"Third Quarter 2026 Outlook: Revenue between $1.135 billion and $1.145 billion"* —— 再乘上近八季平均超額 **+4.25%**（標準差 0.66pp；有紀錄的 27 季中，沒有任何一季低於指引中點）。

**它不是用另類數據建的，而這正是本報告的主要發現。** 我建構了四種下載量訊號構造與一個 hyperscaler 訊號，全部通過同一套時點（as-of）面板、擴張視窗 walk-forward、六個基準模型、配對負對照組與置換虛無檢定。**24 個候選格中，零個勝過最強的樸素基準。** 這些訊號確實帶有 AR(1) 所缺乏的資訊（置換檢定 p=0.002）—— 但那個資訊是**漂移**，而一個設定正確的樸素模型本來就免費提供它。呈現一個訊號加權的營收估計值，等於呈現一個被我自己的驗證推翻的關係。

這個預估立基於三件事：

1. **以指引為錨，天然吸收 regime change。** Datadog 的成長從 24.6%（2025Q1）加速到 35.6%（2026Q2）。以營收歷史為錨的模型必須**推斷**這個斷裂；以指引為錨的規則直接從管理層**繼承**它。該規則在 2026Q2（樣本內最大加速）的 walk-forward 殘差是 **+0.18pp**。
2. **超額分布在近期樣本上是定態的**（近 16 季 ADF p=0.007、KPSS p=0.100），近八季標準差僅 0.66pp。這個穩定性既是 ±$15m 區間可信的原因，也同時是另類數據幾乎沒有增值空間的原因。
3. **另類數據現在的角色是背離監控器，不是估計器** —— 它標示本季何時開始不像過去八季，而那正是 trailing-mean 規則最容易失效的時刻。

## 3. Part 2 — 方法論與結果

### 3.1 時點（as-of）建構

特徵以 **vintage** 形式儲存 —— 每列是一組（季度、特徵、值、`available_from`）—— 因此取用特徵集是一次**過濾**，而非一次判斷。共 1,666 列 vintage、50 個特徵。`available_from` 取財報 8-K 日期，**而非** 10-Q 申報日：8-K 領先 10-Q 的中位數是 1 天，但第四季可達 18 天。揭露落後是實測而非假設：中位數 38 天、範圍 34–47 天，第四季系統性較長（44 天 vs 36–38 天）。

13 個單元測試強制執行這件事，包含一個靜態檢查（特徵建構器絕不引用受前視污染的插補版本）與一個動態檢查（把該載入器換成會拋錯的替身，然後重建整個面板）。

### 3.2 領先—落後分析

兩個目標都是**非定態**（`rev_yoy` ADF p=0.063／KPSS p=0.022；`beat_vs_guide` ADF p=0.079／KPSS p=0.028）。這件事的重要性超過表面 —— 見 §3.4。

交叉相關給出第一個警訊。`dd_abs` 與 `rev_yoy` 相關 0.86–0.89 且在 lag −1 達峰，看起來像個領先指標。但**安慰劑籃** —— `lodash`、`chalk`、`axios`、`react`，與 Datadog 毫無經濟關聯的套件 —— 在 lag −2 到 +2 的相關依序是 **0.72、0.76、0.73、0.73、0.73**。不可能含有任何 Datadog 資訊的套件卻呈現這種水準的**平坦**相關剖面，正是共同趨勢的指紋。

真正具操作意義的是部分季度檢定：前 45 天能否樣本外預測整季？`dd_abs` 對 `rev_yoy` 的 RMSE 比值依序為 **0.734（d30）→ 0.860（d45）→ 0.895（d60）→ 0.975（整季）**。觀測值累積越多，表現越**差**。真實訊號會隨資料增加而銳化，趨勢相位擬合則相反。

**AR(1) 在兩個目標上都是最差或接近最差的基準。** 以題目自己指定的指標（MAPE 與命中率）衡量，最佳的 `rev_yoy` 即時預測是「指引中點 + 近八季平均超額」：MAPE 5.48%、命中率 69.2%，完全不使用另類數據。（八季這個視窗是**事後**選擇，是在觀察到展開式平均受 2020–21 regime 污染後才決定的；它把訊號要跨過的門檻**抬高**而非降低。）

### 3.4 結果

三個候選特徵 × 四個視窗 × 兩個目標 = 24 格，每格都有配對負對照組。以各目標的**最強**基準計分：

| | `dd_rel` | 1.911 | 1.928 | 2.078 | 2.409 |
| | `dd_rel_plc` | 1.470 | 1.516 | 1.536 | 1.576 |
| `beat_vs_guide` vs 隨機漫步 | `dd_abs` | 1.105 | 1.108 | 1.075 | 1.108 |
| | `dd_rel` | 1.347 | 1.295 | 1.254 | 1.294 |
| | `dd_rel_plc` | 1.364 | 1.361 | 1.355 | 1.386 |

**0 / 24。** 任何視窗、任何目標，一格都沒有。

**解釋它的三句話因果鏈。** 對 **AR(1)**，24 格中有 15 格低於 0.9，而置換虛無分布（1,000 次抽樣，特徵值跨季度打亂）平均只產生 0.58 格 —— **p = 0.002**，所以這些特徵**確實**帶有 AR(1) 缺乏的資訊。但一個**純時間指標**走完全相同的管線，同樣打敗 AR(1)（`beat_vs_guide` 比值 0.896），而它含有零 Datadog 資訊。對**最強**基準，同一個置換虛無分布平均產生 0.01 格，而實際觀測值是 **0**。

**那個資訊是漂移，而設定正確的樸素模型本來就有它。**

顯著性檢定確認了這點。24 列經 Diebold–Mariano（HLN 小樣本修正）與 10,000 次 bootstrap 檢驗，恰好只有一個候選格的信賴區間排除 1.0：`dd_abs_d45` 對 `beat_vs_guide`，比值 0.718、CI [0.604, 0.834]、DM p=0.070 —— **而且只對 AR(1)**。同一格對隨機漫步的比值是 1.108、CI [0.534, 1.784]、DM p=0.721。

**訊號 2 敗得更徹底。** Microsoft Intelligent Cloud 成長對 ARIMA(1,1,0) 的比值是 2.912、CI [1.671, 5.970]、DM p=0.025 —— 顯著**劣於**基準。它的方向命中率達 0.846，但誤差是基準的約 3 倍：方向對、幅度大錯，這正是「單看命中率是壞指標」最清楚的例證。

## 4. 失敗的原因：下載量與營收的耦合已經衰減

這是本報告最具可移轉性的發現，適用於任何嘗試以下載量做 SaaS 即時預測的人，不只適用於 Datadog。

Part 1 的經濟論證是：儀器化套件下載量代理計費單位。若此成立，則「每一美元營收對應的下載量」應大致穩定。事實並非如此：

> **每百萬美元營收對應的下載量：21,818 → 97,228，樣本期內 +346%。Spearman ρ = +0.927，p < 0.0001，28 季近乎單調。**

代理關係已衰減約 4.5 倍。把下載量成長映射到營收成長的模型假設耦合穩定；這個耦合在此明確不成立。walk-forward 的失敗不是小樣本意外 —— 它正是一個衰減中的代理關係應該產生的結果。

**最顯而易見的解釋並不成立。** 若下載量中 CI/CD 重拉（而非實際部署）的佔比在上升，工作日集中度應該上升。事實並非如此：工作日／週末比從 6.39 降到 5.61，斜率 −0.006/季、p = 0.77 —— 持平到略為**下降**。第二個關於改版窗口集中度的檢定在**設計上即檢定力不足**（dd-trace 發版過於頻繁，7 天窗口覆蓋大部分日曆），故據實報告為檢定力不足，而非報告為虛無結果。

我無法用公開資料把這個衰減歸因到特定機制。以下候選解釋維持**列名而不暗示已排除**：鏡像與代理流量成長、容器映像重建、AI coding agent 產生的重複安裝，以及一個結構性事實 —— 下載量未加權而營收以金額加權，一家企業客戶與一個業餘使用者計為相同。

## 5. 限制，以及資料不支持的結論

**區間是有條件的。** ±$14.7m **僅**反映超額的歷史變異。指引抽取誤差為零（每個數字都已從 EDGAR 重新抓取並與逐字原文對照）。超額分布的 regime 風險對本次預估屬二階：平坦 trailing-mean 給 $1,188m，趨勢外推的替代算法給 $1,195m，$7m 的差距落在區間之內。區間**未**涵蓋的是：指引哲學改變、客戶集中度事件、併購。正式表述為：本區間**條件於超額分布維持定態** —— 該條件在近 16 季獲得支持，在近 8 季則略顯緊張（Spearman ρ=+0.69，p=0.058）。

**樣本數主導一切。** 27 個可用季度、13–14 個樣本外預測點。在這個 n 之下，本報告中每一個命中率都無法與隨機區分（所有情況雙尾二項檢定 p ≥ 0.18）。Granger 檢定有跑，但僅作描述性報告；在 n≈24 下它無法支持因果宣稱，而且負對照組「Granger 導致」營收的程度與訊號本身相當。這個樣本數也是模型只用最多兩個預測變數的 OLS 的原因 —— 梯度提升或序列模型會把趨勢擬合得漂亮，卻什麼也驗證不了。

**在 0.34% 的資料上就會翻轉的結果，不是結果。** npm API 在 3,512 天中有 12 天回傳全站零值。移除它們會使跨 registry 相關係數從**低於**其安慰劑（0.932 vs 0.951）變成**高於**（0.972 vs 0.961）。這種脆弱性本身就是「這個 26 週的相關性檢定無法支持任一方向結論」的證據 —— 它被當成無定論判定的**理由**來報告，而不是當成拯救了訊號的修補。

**已承載但未解決的偏誤。** 下載量 ≠ 安裝數；籃子組成漂移迫使剔除三個在樣本起點尚不存在的 Datadog 套件（納入它們會使 YoY 成長失真達 0.31 對數點，而且差分**無法**消除，因為只有分子籃改變了組成）；PyPI 歷史僅 181 天；訊號 3 與 4 只描述、未測試。

## 6. 產品化 — 這套東西作為 agent 工作流的樣貌

頭條結果本身就是產品洞察。**Datadog 營收最好的即時預測，是公司自己的指引加上近期超額紀錄，而四種另類數據構造都無法改善它。** 對一個投研 agent 平台而言，價值因此不在於找到更多訊號，而在於那套讓分析師 —— 或 LLM —— 不會把趨勢誤認為訊號的紀律。三個元件，本專案都親手建過：

**帶元資料的訊號登錄表。** 每個訊號都帶著頻率、延遲、歷史、涵蓋範圍、成本，以及最關鍵的：它的**配對負對照組**與**組成規則**。對照組不是可選的元資料 —— 它正是把一個 0.79 的相關係數變成一個被否決假設的東西。一個儲存訊號卻不儲存其對照組的登錄表，預設就會出貨偽陽性。

**把時點（as-of）vintage 管理當成一級服務。** 前視偏誤是 LLM agent 的特徵性失效模式：一個被要求提供「Datadog 第二季營收」的 agent 會抓來源的**當前**值，而不是決策日當時可得的值。在本專案中，這個區別在第四季揭露上價值達 18 天，並迫使區分「只回看」與「置中」兩種插補。vintage 層應該屬於基礎設施，其單元測試 —— **任何特徵的來源時間戳都不得晚於 as-of 日期** —— 應該跑在 CI 裡，而不是活在分析師腦中。

**自動化評估迴圈。** 決定本專案結論的那條管線完全是機械式的：包含漂移調整樸素模型的完整基準集、走同一條路徑的配對安慰劑、以置換虛無檢定為事後自由度定價的網格、以及帶 bootstrap 區間的 DM 檢定。它應該對每個候選訊號自動執行並回傳判定，而不是依賴分析師記得去問「AR(1) 是不是一個公平的對手」。單一價值最高的元件是安慰劑路徑 —— 它以多跑一次的成本，把「我們找到訊號了」轉換成「我們找到趨勢了」。

**可重用性。** 要把這套指向 SNOW 或 MDB 需要三處改動 —— CIK 與營收標籤、一組訊號籃連同其對照籃與安慰劑籃、以及重新指向該發行人措辭的指引抽取器。其餘皆與標的無關。**不能移轉的是結論**：對一個指引可靠度較低的發行人，同一條管線很可能會拱出不同的輸入，而這正是「先跑基準」的意義所在。
